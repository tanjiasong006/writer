# 产品与技术决策

已确定、需要长期保持的决策。修改任何一条前，先与产品负责人确认并更新本文件。

## 1. 正文文件名

正文文件名由章节编号决定（`content/ch_2_1.md`），ChapterId 是稳定内部身份。
编号变化时文件必须重命名，一致性由 persistence 层的保存事务保证。
详见 `docs/project-format.md` 第 2、5 节。**不得改用 ChapterId 作为文件名。**

## 2. 编辑器

- MVP 使用 CodeMirror 6 做 Markdown 源码编辑，不做完整 WYSIWYG。
- 提供常用操作入口：图片、表格、列表、粗体、斜体、引用、代码块，用户不必完全手写 Markdown。
- 编辑器不得对未编辑的正文做任何规范化；只有用户真正修改的章节才会被写回。

## 3. 章节标题与正文

- 章节标题只存在于文档结构（manifest）中，Markdown 正文不重复保存章节标题。
- 章节编号不存入正文，也不存入 ChapterNode；编号永远由树结构推导（`chapter_numbering`）。
- 预览和导出时根据章节树深度和编号生成章节标题。

## 4. 保存

- 自动保存（防抖）+ Cmd/Ctrl+S 手动保存。
- **dirty 状态的边界**：只有当存储层明确返回"本次保存已提交"时，才把
  "发起保存时的那份快照"标记为已保存。
  - 保存失败（无论在提交点前还是后）→ 文档保持 dirty，错误对用户可见，之后会重试。
  - 保存进行中用户继续编辑 → 保存成功后文档仍为 dirty（新编辑不属于那份快照）。
  - 同一时间最多一个保存在进行；期间的保存请求合并为之后的一次保存。
- 关闭窗口时若仍为 dirty，先尝试保存；保存失败必须让用户选择，不能静默丢弃。

## 5. 导出

- Word / PDF 导出随 Writer 自带，**不依赖用户安装 Pandoc 或 LibreOffice**。
- Word：Rust `docx-rs` 生成。
- PDF：优先内嵌 Typst（实现方案，不是产品约束）。若发现明显的跨平台、体积或字体问题，
  先与产品负责人沟通再调整。
- 预览与导出共用同一个 Markdown 解析器（Rust `pulldown-cmark`），保证三者结构一致。

## 6. 字体

- 字体按"角色"配置：正文、标题、等宽；每个角色是一个有序的候选字体族列表（fallback 链），
  同时包含拉丁字体与中文字体，覆盖 macOS / Windows / Linux 的常见字体。
- 选择字体时按列表顺序使用第一个可用的字体，逐字形回退。
- 预留"随应用打包字体"的位置：打包字体始终参与查找，未来可放入开源中文字体保证一致性。
- 找不到任何可显示中文的字体时，导出给出明确警告，而不是静默输出缺字。
- 字体配置集中在一处（Rust `export::fonts`），不在各导出器里各写一份。
- 打包字体：把 .ttf / .otf / .ttc 放入应用资源目录下的 `fonts/`（Tauri `bundle.resources`）即参与 PDF 排版的字体查找；
  要让它成为首选，把它的字体族名加到 `export::fonts::families` 对应角色列表的前面。
  Word 只写字体名，由用户机器上的 Word 负责替换。

## 7. 稳定性

- release 构建使用 `panic = "unwind"`：第三方排版库（Typst、docx-rs）遇到异常输入时 panic 只让本次导出失败，
  不会让整个应用退出。导出与预览都在后台线程执行，panic 被转换为普通错误返回给界面。
- 来自用户项目的数据（图片、正文）中的任何问题都不能让应用崩溃：图片解码带尺寸 / 内存上限，
  失败时以占位文字输出并在导出报告中列出。
